# Bored Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An installable, offline, ultra-light PWA holding 36 instantly playable fidget, arcade and brain mini games with one-tap switching.

**Architecture:** Vanilla TypeScript with no UI framework. A plain-DOM shell (hash router, home grid, player with top bar) hosts games. Each game is a lazy-loaded module that implements the `GameFactory` contract and uses a shared micro-engine in `src/core/` (stage, loop, input, audio, haptics, storage, overlay). Rule-heavy games keep their rules in a pure `logic.ts` that is unit tested.

**Tech Stack:** Vite 7, TypeScript 5 (strict), vite-plugin-pwa, Vitest, @playwright/test (Chromium only), ZzFX (vendored, MIT).

**Spec:** `docs/superpowers/specs/2026-10-09-bored-game-design.md`

## Global Constraints
- No runtime dependencies other than vendored ZzFX. No images or audio files; everything is drawn or synthesized in code.
- Initial load 35 KB gzipped or less; each game chunk 12 KB gzipped or less; total 400 KB gzipped or less (enforced by `npm run size`).
- Any game is playable less than 2 s after tapping it, with no tutorial screens. Each game gets at most a one-line hint, which fades on the first input.
- Home and Shuffle are reachable from inside every game. Esc goes home and N shuffles on desktop.
- Works fully offline after the first visit (service worker precaches every chunk).
- Storage keys live under the `bg1:` prefix; all persistence goes through `Store`.
- Original game names only (no Flappy, Plinko, Simon or Pop It).
- Portrait-first with mouse and keyboard support; respects `env(safe-area-inset-*)`.
- `destroy()` must cancel every animation frame, timer, listener and audio node the game created.

## Review Focus
1. **Fast switching** (Shuffle tapped 40× quickly): no stacked animation loops, no leaked listeners, no errors. The e2e shuffle-storm test in Task 4 covers this.
2. **Resize or rotation mid-game:** the canvas re-fits and the game keeps working without a blank screen. The stage resize unit test (Task 2) and the e2e viewport-change step (Task 4) cover this.
3. **Tab hidden, then shown:** the game pauses and doesn't jump a huge time step on return. The loop dt-clamp unit test (Task 2) covers this.
4. **localStorage unavailable or corrupt** (private mode, JSON garbage): the app still runs with defaults. Covered by a Store unit test (Task 2).
5. **Multi-touch and mouse on the same game:** both work, and a second finger doesn't break drag games. Covered by input unit tests on pointer-id tracking (Task 2).

## Game tasks (Waves 1–3)

Every game task has the same shape, and all of the following apply to each one.

**Files:** create `src/games/<id>/index.ts` (+ `logic.ts` and `tests/unit/<id>.test.ts` where listed). Modify `src/games/registry.ts` to add the `GameMeta` entry.

**Interface:** `export default ((ctx) => canvasGame(ctx, s => ({ ... }))) satisfies GameFactory`. DOM-based games (Switchboard, Color Clash, Math Sprint, Odd Color) build DOM inside `ctx.root` and must return `{ pause, resume, destroy }` that cleans it up.

**Every game must:**
1. Draw on its first frame.
2. Call `ctx.hint()` with at most one line.
3. Play an `sfx` sound and a `haptics` pulse on its core action.
4. Score through `ctx.gameOver` (arcade or brain) or keep a running stat in `ctx.hud` (fidget).
5. Restart on retry without re-creating the stage.
6. Pass the e2e loop unchanged.
7. Keep its chunk at 12 KB gzipped or less.

**Steps for each wave:**
1. For logic games: write the failing logic tests, run them (FAIL), implement `logic.ts`, run them (PASS).
2. Implement each game and register it.
3. Run `npm test && npm run build && npm run size && npm run e2e` (all PASS).
4. Commit `feat(games): wave N`.
